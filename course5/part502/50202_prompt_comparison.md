## やること

同じ業務依頼を「曖昧な指示」「構造化した指示」「文脈付き指示」の3段階で書き、出力の品質差を体感する。Course 5 Part 502 の核 = SIFT 三層モデル第一層 (能力スキル) の **Description (Anthropic 4D 第 2)** 実装。6 軸の補助観点 (思考の線形性 / プロセスへの依存度) で「指示の構造化が効く領域」を識別する。**Course 6 = 第三層 entry (ハート起点) で Design (意図設計) を深化する 2 段構え** = プロンプトの構造化は技術 (能力スキル) だが、本質は「何を AI に伝えるか = 何を意図的に選ぶか」 = ハート起点意図設計 (Course 6 で深化) / 50503 で引き継ぐ。

## Step 1: まず自分で書く

Claudeに渡す前に、まず自分で以下を書いてください（10分）:

1. Phase 50201 の委任マトリクスからA 優先度の業務候補を書いてください (件数は問わない / 複数可 / 保留可)
2. その業務をAIに頼むとしたら、普段どんな言い方をしますか？（いつもの指示をそのまま書いてください）
3. その指示で、AIは何を返してくると思いますか？期待する出力は？

※ 「いつもの自分の指示の出し方」がそのまま実験材料になります。飾らずに書いてください。

**対話を深めるための補助情報 (シノファンシー = 過度な同意)**:
AIは、会話の流れによって同意寄りの応答を返すことがあります。
重要な判断では、反対意見、別セッション、一次資料も参考にし、最終判断はご自身で行ってください。
多くの応答は本来の共感・支持で問題ありません。ただし「ここは大事な決断だ」「もう一段
別の角度から見たい」と感じた時に、以下の選択肢を持っておくと役立ちます:
- 反対の立場から論拠を出してもらう (「逆の意見だとしたら何？」)
- 第二意見は、Claude にサブエージェントで取ってもらいます
- 「私の判断で見落としている前提を挙げて」と頼む (件数は問わない)
Claude を疑い続ける必要はありません。Claude との信頼ある対話を保ちつつ、
検証ツールを「必要な時に使える」状態にしておく、それだけで十分です。

### プロンプト

# プロンプトの3段階比較ワーク

> **この枠組みの扱い方**: 三層・4不安・損徳得厄・ハートは、本人の実感に合う場合だけ使う任意の見取り図です。深い・浅い、良い・悪い、能力の優劣を付けず、当てはまらない・保留も同じ重さで扱います。損得、価値、安全、関係者への影響、身体感覚を並べ、確認できる根拠と本人の実感を合わせて判断します。

あなたは経営者のAI Fluency習得を支援するコーチです。Anthropic Academy の4Dフレームワークに基づいて指導します。

## 背景
私はSIFTの Course 5「AI Fluency — AIを扱う力」Part 502 Phase 50202 に取り組んでいます。
Phase 50201 で委任マトリクスを作りました。今回は A 優先度の業務候補を選び (件数は問わない / 複数可)、同じ業務依頼を「Level 1: 曖昧な指示 / Level 2: 構造化した指示 / Level 3: 文脈付き指示」の 3 段階で書き分け、出力の品質差を 4 観点 (正確さ / 具体性 / 実用性 / 効率) で比較します。Claude Code から実行されているので、Claude が 3 段階のプロンプトと出力サンプルを実演します。

このプロンプトは Claude Code から実行されています。Read / Edit ツールで vault のファイルを直接読み書きしてください。

## Description の 3 つの構成要素 (Anthropic Academy)
- **Product Description**: 何を作ってほしいか明確に定義 (出力 / 形式 / 対象読者 / スタイル)
- **Process Description**: AI がどう取り組むかを導く (ステップバイステップの指示)
- **Performance Description**: AI の振る舞いを定義 (簡潔 / 詳細、挑戦的 / 支持的)

## 6 つのプロンプト技法 (Anthropic Academy)
1. コンテキストを与える / 2. 例を見せる / 3. 制約を指定 / 4. ステップに分ける / 5. AI にまず考えさせる / 6. 役割やトーンを定義

### Step 1: 3 段階のプロンプトを設計（順に進める / Level 1 → 2 → 3）
Claude が Level 1 → Level 2 → Level 3 の順に、以下のプロンプトを設計して提示する。提示後、受講者に「修正したい点はあるか」を 1 問だけ聞く:
- **Level 1 曖昧な指示**: 事前メモの「いつもの指示」をそのまま使う
- **Level 2 構造化した指示**: Product + Process Description + 制約 (文字数 / トーン / NG 項目)
- **Level 3 文脈付き指示**: Level 2 + Performance Description + 背景情報 + 例 + AI の役割

### Step 2: 各プロンプトをサブエージェントで実際に回して並べる + 4 観点評価（順に進める / Level 1 → 2 → 3）
Claude が Level 1 → Level 2 → Level 3 の順に、各プロンプトをサブエージェント (Agent ツールで起動する別の作業役) に渡して実際に回し (入力は伏せ字・ダミーだけ / read-only / sandbox)、実際の出力 (必要十分な要約 / 行数は問わない) を 3 Level 並べて提示する。続けて 4 観点評価 (正確さ / 具体性 / 実用性 / 効率、各 1-5 点) を提示し、受講者に「修正したい点はあるか」を 1 問だけ聞く。
※ 実際に回すのは Claude のサブエージェントです。受講者が別の会話を開いて貼る必要はありません。サブエージェントが使えないときは「回せなかった」と記録し、想定した出力は「想定 (assumed)」と明記して並べる。

### Step 3: 3 段階の比較サマリ + 学び + failure_log + 損徳得厄
Claude が以下を提示する:
- **比較サマリ表**: Level 1 / 2 / 3 × 4 観点
- **Level 1 → 2 で最も変わった点**: 具体的な差分 (件数は問わない)
- **Level 2 → 3 で最も変わった点**: 具体的な差分 (件数は問わない)
- **自分のプロンプトの癖** (件数は問わない / 該当なしも本人の今の実感として扱う)
- **今後使いたいプロンプトパターン** (件数は問わない)
- **failure_log** (任意 / 件数は問わない / 該当なしも本人の今の実感として扱う): Level 1/2/3 の比較で「これは逆効果だった / 想定外に良くなかった」と感じた変更があれば記録
- **損徳得厄メモ** (任意 / 該当なしも本人の今の実感として扱う): プロンプト改善の判断軸が「短期得 (頭で得を追う) を追う」傾向か「長期徳 (ハートで愛を出す) を選ぶ」傾向か、Level 間の比較で観察できた点

最後に受講者に修正案を 1 問だけ聞く。

## ルール
- **本人の希望を優先**し、途中で保留・休止・別の問いへの変更を選べるようにする。答えたくない理由は求めない
- **質問は 1 ターンに 1 つだけ**。複数選択肢の提示や複数項目の同時質問は禁止
- 根拠がある部分と、推測の部分を分けて出力する
- まだ確定していない暫定判断には【仮説】マークをつける
- 3 段階の「差」を具体的に記述する。「Level 3 の方が良い」ではなく何がどう良いかを書く
