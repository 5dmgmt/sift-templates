## やること

業務課題に対して (件数は問わない / 複数可)、Description→出力→レビュー→改善を周回し、反復的に品質を高めるプロセスを練習する (件数は問わない / 周数は本人が実感できる改善が見えるまで)。この Phase は学習の区切りであり、能力の到達を保証しない。failure_log と損徳得厄の観点は、本人の実感に合う場合だけ任意で記録する。

## Step 1: まず自分で書く

Claudeに渡す前に、まず自分で以下を書いてください（10分）:

1. Phase 50202 で品質差が見えた業務候補 (件数は問わない / 複数可 / 保留可)
2. Level 3 のプロンプトでもまだ「ここが物足りない」と感じた点は？
3. 「もう1回やり直すなら、ここを変える」と思うポイントは？

※ 前回の反省がそのまま今回の出発点になります。

**対話を深めるための補助情報 (シノファンシー = 過度な同意)**:
AIは、会話の流れによって同意寄りの応答を返すことがあります。
重要な判断では、反対意見、別セッション、一次資料も参考にし、最終判断はご自身で行ってください。
多くの応答は本来の共感・支持で問題ありません。ただし「ここは大事な決断だ」「もう一段
別の角度から見たい」と感じた時に、以下の選択肢を持っておくと役立ちます:
- 反対の立場から論拠を出してもらう (「逆の意見だとしたら何？」)
- 第二意見は、Claude にサブエージェントで取ってもらいます
- 「私の判断で見落としている前提を挙げて」と頼む (件数は問わない)
Claude を疑い続ける必要はありません。Claude との信頼ある対話を保ちつつ、
検証ツールを「必要な時に使える」状態にしておく、それだけで十分です。

## ルール
- **本人の希望を優先**し、途中で保留・休止・別の問いへの変更を選べるようにする。答えたくない理由は求めない
- **質問は 1 ターンに 1 つだけ**（Step 0 の事前メモ未記入時の 3 問まとめ提示は唯一の例外）
- 根拠がある部分と、推測の部分を分けて出力する
- まだ確定していない暫定判断には【仮説】マークをつける
- 各周回の改善点は具体的に記述する (「良くなった」ではなく何がどう変わったか)
- 最終周回でも完璧である必要はない。「次にやるならここを変える」を残して OK
- 改善が逆効果だったケースも記録する (failure_log)。失敗パターンは今後の資産
