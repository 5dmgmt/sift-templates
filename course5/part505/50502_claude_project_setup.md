### Claude Project とは
claude.ai の機能で、プロジェクトフォルダに文脈ファイル (テキスト / PDF 等) を入れておくと、そのプロジェクト内の全会話で AI がその文脈を参照できる仕組み。

   - 今すぐ AI に相談したい業務課題を思いつく分だけ (件数は問わない / カテゴリ・状況の抽象化のみ)
   - その課題を AI に相談するとき、前提として知っておいてほしい「自分の情報」は何か

### Step 1: プロジェクト設計（プロジェクト名 + 目的 + 文脈ファイル選定）
Claude が以下をまとめて提示する:
- **プロジェクト名**: 何のためのプロジェクトか
- **目的**: どんな場面で使うか
- **文脈ファイル選定**: Course 1-5 の成果物から、入れるファイル (件数は問わない / 理由付き、redaction 確認済) / 入れないファイル (件数は問わない / 理由付き、PII / secret / 実プロンプト含有・redact 不能・denylist 該当などを明記)
- **redacted context pack のディレクトリ**（例: `~/sift/course5/part505/_context_pack/`）

提示後、受講者に「修正したい点はあるか」を 1 問だけ聞く。

### Step 2: Project Instructions の設計 + 構築手順ガイド
Claude が Project Instructions (役割 / トーン / 制約 / 50403 由来の停止条件 / 50401 由来の機密データ取り扱いルール) を設計して提示する。
続いて claude.ai での構築手順をガイド:
1. claude.ai → Projects → New Project
2. プロジェクト名と Instructions を貼り付け
3. 文脈ファイル (Step 1 で選定 / redacted context pack のみ) をアップロード
4. テスト会話を開始

受講者に「Instructions に修正したい点はあるか」を 1 問だけ聞く。

### Step 3: 業務相談テストのプロンプト設計（順に進める / 件数は問わない）
事前メモの業務課題について、Claude が順に以下を提示し、受講者に「修正したい点はあるか」を 1 問だけ聞く (件数は問わない / **プロンプト案は redact 済み / 実顧客名・実プロジェクト名なし**):
- **テストプロンプト案**: claude.ai の Project に投げる文面（抽象化済み）
- **想定される文脈活用ポイント**: どのファイルが効くと予想されるか
- **評価観点**: 文脈なしの場合との差をどこで測るか（出力品質 5 段階 / 文脈活用度 / 専門家確認分離が機能するか / 危機兆候時の応答）

受講者は claude.ai でテストを実行し、結果 (出力品質 5 段階 / 文脈が活きた点 / 活きなかった点 / 改善点) を Claude Code に戻して報告する。

### Step 4: 成果物を vault に書き戻す
受講者からテスト結果が戻ってきたら、`~/sift/course5/part505/50502_claude_project_setup.md` の Step 3「成果物」セクションを Edit で書き込む。

## ルール
- **進め方の確認・好みヒアリングは禁止**。上記の手順で決め打ちで進める
- **質問は 1 ターンに 1 つだけ**（Step 0 の事前メモ未記入時の 3 問まとめ提示は唯一の例外 / Step 1-4 では厳守）。複数選択肢の提示や複数項目の同時質問は禁止
- 根拠がある部分と、推測の部分を分けて出力する
- まだ確定していない暫定判断には【仮説】マークをつける
- 文脈ファイルに機密データ (Phase 50401 の policy に基づく) を入れないこと
- プロジェクトは「完成」ではなく「育てていく」もの
