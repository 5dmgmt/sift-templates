## Step 1: まず自分で書く

Claudeに渡す前に、まず自分で以下を書いてください（10分）:

1. 20302の仕分けで「即やめる」に入れたもののうち、本当に明日からやめられるものは？
2. 委任したいタスクの相手に、どう伝えるか想像できるか？
3. 「やめたら迷惑がかかる」という恐れはどこから来ているか？

※ 正解はありません。今の感覚で書いてください。この事前メモがあるとClaudeとの対話が深くなります。

**対話を深めるための補助情報 (シノファンシー = 過度な同意)**:
AI との深い対話では、応答が肯定的に揃いやすい場面が起こりえます (Anthropic 研究 2026)。
これは Claude の限界ではなく、対話のメカニズムとして知っておく豆知識です。
多くの応答は本来の共感・支持で問題ありません。ただし「ここは大事な決断だ」「もう一段
別の角度から見たい」と感じた時に、以下の選択肢を持っておくと役立ちます:
- 反対の立場から論拠を出してもらう (「逆の意見だとしたら何？」)
- 第二意見を別 Claude session で取る
- 「私の判断で見落としている前提があれば該当する分だけ挙げて」と頼む (件数は問わない)
Claude を疑い続ける必要はありません。Claude との信頼ある対話を保ちつつ、
検証ツールを「必要な時に使える」状態にしておく、それだけで十分です。

- 件数主義を採らない。1 区分あたり 0 件 (= 該当なし / すでに任せ済 / 全て最善最適 / 在り方で答えている等の受容応答 + その理由) でも genuine な答えなら完了

### Step 1: やめるタスクの停止日 + 関係者連絡文を作る (Day 1 / 7 日以内対象は目安 3-5 件まで cap / 件数は問わない / 残りは backlog)

- **停止日**: 7 日以内のいずれか
- **関係者への連絡 (vault 記録)**: 「相手の役割 (例: 元上司A / 取引先B社の担当者) / 連絡チャネル種別 (例: メール / Slack)」だけを vault に残す
- **連絡文の placeholder 雛形**: 「{相手の役割} 様」「{タスク概要} を 〇月〇日で停止します」など。**実宛先・実本文は vault 外 (メーラー下書き等) で管理**

### Step 2: 委任タスクの引き継ぎ文書を作る
20302 の「人に渡す」タスクについて、Claude が以下を 1 ターンに 1 件ずつ埋める:
- **依頼文**: 相手に送るメッセージ (5〜8 行、80% で渡す前提)
- **引き継ぎ手順**: 5 つ以下の箇条書き手順
- **依頼日**: 7 日以内のいずれか

「完璧な引き継ぎを目指さない (80% で渡して、残りは相手が聞いてくる前提)」を Claude が守る。

### Step 3: AI 下書き化タスクのプロンプト雛形を作る
20302 の「AI 下書き化」タスクについて、Claude が以下を埋めた一覧を提示する:
- **プロンプト概要**: そのタスクを Claude に投げる際の依頼文の雛形 (4〜6 行)
- **人間の仕上げ範囲**: 1 行

### Step 4: Day 1 の実行 (genuine にあれば / 件数は問わない)
上記 3 区分の中で **今日 genuine に実行したいものがあれば**、Claude が最も実行しやすい 1 件を選んで提案する。受講者に「これを今日実行するか / 別のものに入れ替えるか / 今日は実行しないか」を 1 問だけ聞く。
**0 件 = 該当なし / すでに任せ済 / 全て最善最適 / 在り方として答えている 等の受容応答 + その理由 でも完了**。「強いて言えば」レベルでの 1 件実行は記録対象外。
実行した場合、Claude が以下を聞いて記録する (1 ターンずつ):
- 実行日
- やったこと (1 行)
- 結果・気づき (1〜2 行)

実行しなかった場合、Claude が「今日実行しなかった理由 / すでに着地している場合の在り方」を 1 行記録する。
