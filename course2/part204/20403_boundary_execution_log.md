## Step 1: まず自分で書く

Claudeに渡す前に、まず自分で以下を書いてください（10分）:

1. 20402 の境界線設計で、最も優先度が高い相手は？ (件数は問わない / 目安 1-3 人 / 心理負荷管理のため絞る)
2. その人に伝えるとき、一番怖いことは何か？
3. 「伝えた後にどうなってほしいか」の理想を書く

※ 正解はありません。今の感覚で書いてください。この事前メモがあるとClaudeとの対話が深くなります。

**対話を深めるための補助情報 (シノファンシー = 過度な同意)**:
AI との深い対話では、応答が肯定的に揃いやすい場面が起こりえます (Anthropic 研究 2026)。
これは Claude の限界ではなく、対話のメカニズムとして知っておく豆知識です。
多くの応答は本来の共感・支持で問題ありません。ただし「ここは大事な決断だ」「もう一段
別の角度から見たい」と感じた時に、以下の選択肢を持っておくと役立ちます:
- 反対の立場から論拠を出してもらう (「逆の意見だとしたら何？」)
- 第二意見を別 Claude session で取る
- 「私の判断で見落としている前提があれば該当する分だけ挙げて」と頼む (件数は問わない)
Claude を疑い続ける必要はありません。Claude との信頼ある対話を保ちつつ、
検証ツールを「必要な時に使える」状態にしておく、それだけで十分です。

> **「安全 / 要確認」第 6 区分の保護を継承 (重要 / 20401/20402 から / 実行 Phase なので最厳守)**: 20401/20402 で「安全 / 要確認」に分離した関係 (= DV / ストーカー / 虐待 / ハラスメント / 暴力 / 違法行為 / 権力濫用 / 労務・法務・医療・介護・安全上の義務) は:

> - 「最優先関係」の選定からも除外
> - 危険な相手への連絡文生成 / 送信判断には絶対に進まない
> - 該当時は **安全確保 / 信頼できる第三者 / 専門家 / 緊急窓口 / 法務 / 医療** を最優先

> **第三者 PII redact 継承 (重要 / 20401/20402 から)**: 20403 成果物は 20501/20503 から再読込されるため、**PII が後続プロンプトへ増幅伝播する**:
> - **相手は匿名 ID** (= 「同僚 A」「家族 1」等) で記録
> - **対応表 (匿名 ID ↔ 実名) は AI に渡さないローカル管理** (= CLAUDE.local.md / 1Password / 紙メモ)
> - **メッセージ草案 / 実送信ログ は placeholder / 役割ベース** (= `{相手の役割}` / `{関係性}` / 実名・連絡先は入れない)
> - **相手の反応・身体反応** は **必要最小限の非機密要約** (= 個人を特定できる詳細は書かない / 評価・告発・契約詳細は書かない)
> - 個人名 / 連絡先 / メッセージ本文 / 社員評価 / 顧客 PII が混入したら **伏せ字化** + 保存しない

### Step 1: 最優先関係を確定 (目安 1-3 / 件数は問わない / 0 件 = N/A 可)
20402 と事前メモを踏まえて、Claude が「最優先関係」候補を **該当する分だけ** 提示する (目安 1-3 / 心理負荷管理のため絞る / 0 件なら N/A とし、20402 の再設計が必要なら deferred_for_safety / needs_expert_review を記録)。
受講者に「この候補で進めるか / 入れ替えるものはあるか / 0 件 = 該当なしで完了か」を 1 問だけ聞く。
確定したら即 Step 2 へ (0 件で N/A の場合は Step 5 へ進み、その旨を成果物に記録)。

### Step 2: メッセージ草案を作る（1 ターン 1 関係 / 件数は問わない）
最優先関係それぞれ (目安 1-3 / 件数は問わない) について、Claude が以下 4 原則を満たすメッセージ草案 (5〜10 行) を提示する:
- 相手を責めない
- 自分の状態と希望を伝える
- 具体的な提案を含める
- 相手にも選択肢を残す

提示後、受講者に「修正したい点はあるか」を 1 問だけ聞き修正する。

### Step 3: 反応シナリオを 3 通り想定（1 ターン 1 関係）
各関係について、Claude が以下 3 シナリオの「相手の反応」と「自分の対応」をまとめた表を提示する:
1. **受け入れてくれた場合**
2. **反発された場合**
3. **無視された場合**

### Step 4: Day 1 の実行 (genuine にあれば / 件数は問わない / 0 件可)
最優先関係の中で **今日 genuine に送りたいものがあれば**、Claude が最も実行しやすい 1 件を選んで提案する。受講者に「これを今日送るか / 別のものに入れ替えるか / 今日は送らないか」を 1 問だけ聞く。
**0 件 = 該当なし / 心の準備が整っていない / 専門家確認が先 / すでに着地している 等の受容応答 + その理由 でも完了**。「強いて言えば」レベルでの 1 件強制送信は記録対象外。
実行した場合、Claude が以下を 1 ターンに 1 つずつ聞いて記録する:
- 実行日
- 状態 (sent / scheduled / deferred_for_safety / needs_expert_review)
- 実際に伝えた内容 (placeholder 要約 / 実本文は vault 外)
- 相手の反応 (要約)
- 自分の身体反応
- 気持ちの変化
- 次の調整

実行しなかった場合、Claude が「今日送らなかった理由 (心の準備 / 専門家確認待ち / すでに着地 等) / 状態 (scheduled / deferred_for_safety / needs_expert_review)」を 1 行記録する。

### Step 5: 成果物を vault に書き戻す

## ルール
- **進め方の確認・好みヒアリングは禁止**。上記の手順で決め打ちで進める
- **質問は 1 ターンに 1 つだけ**。複数選択肢の提示や複数項目の同時質問は禁止
- 根拠がある部分と、推測の部分を分けて出力する
- まだ確定していない暫定判断には【仮説】マークをつける
- 私が別途確認すべき点があれば最後にまとめる
- 完璧なメッセージを目指さない。伝えることが目標
