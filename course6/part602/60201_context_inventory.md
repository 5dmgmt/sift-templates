## Step 1: まず自分で書く

Claudeに渡す前に、まず自分で以下を書いてください（10分）:

1. SIFT Course 1-5で作った成果物のうち、今も見返すものはどれ？
2. 「これはAIに渡したい」と思う成果物はある？
3. 自分のObsidian vaultは今どんな状態？（整理されている/散らかっている/ほぼ空）
4. 「この情報があればAIの出力が良くなるのに」と感じることは？

※ 完璧なリストでなくて大丈夫です。思いつくままに書いてください。

**対話を深めるための補助情報 (シコファンシー = 過度な同意)**:
AIは、会話の流れによって同意寄りの応答を返すことがあります。
重要な判断では、反対意見、Claude のサブエージェントの意見、一次資料も参考にし、最終判断はご自身で行ってください。
多くの応答は本来の共感・支持で問題ありません。ただし「ここは大事な決断だ」「もう一段
別の角度から見たい」と感じた時に、以下の選択肢を持っておくと役立ちます:
- 反対の立場から論拠を出してもらう (「逆の意見だとしたら何？」)
- 第二意見は、Claude にサブエージェントで取ってもらいます
- 「私の判断で見落としている前提を 3 つ挙げて」と頼む
Claude を疑い続ける必要はありません。Claude との信頼ある対話を保ちつつ、
検証ツールを「必要な時に使える」状態にしておく、それだけで十分です。

  3. **Course 1-5 成果物 allowlist Glob**: `~/sift/course{1,2,3,4,5}/part*/[0-9]*.md` (= Phase ID で始まる成果物 .md のみ)
  4. **realpath 検証**: Read 前に realpath で canonical path を確認し、`~/sift/course{1..5}/part*/` 配下でないもの、symlink、`..` を含むもの、`op://` / secret manager reference を含むものは停止
- **Edit 対象 (allowlist、これ以外は触らない)**:
  - 作業ファイルの Step 3「成果物」セクション + チェックリスト ✓ のみ

  - symlink / `..` / realpath 検証で `~/sift/course{1..5}/part*/` 配下でないもの

#### 0-B: 「AI に渡すと有用」分類の redaction / secret 判定
- 分類前に各ファイルが下記のいずれかを含むかを判定:
  - PII (顧客名 / 社員名 / 個人連絡先 / 住所 / 生年月日)
  - 契約金額実値 / 売上数値 / 報酬額 / 取引先固有名

  - API key / Supabase JWT / `SUPABASE_SERVICE_ROLE_KEY` / `sb_secret_*` / GOCSPX- / OpenAI sk- / Authorization 生値

  - 顧客固有 SOP / 取引先固有メモ / 法務文書 / 医療情報
- 含む場合は分類を以下 4 区分で判定:
  - **渡せる**: PII / secret 等を含まない or 既に redact 済み (= AI に直接渡せる)
  - **加工必須**: 含むが redact / 抽象化すれば渡せる (= 60202 で redact 加工してから使う)
  - **渡さない**: redact 不能 or 業務上 raw で必要 (= 自分だけが読む)
  - **専門家確認**: 法務 / 医療 / 税務 / 労務 / 本番 Supabase / RLS / service_role / 課金 / 顧客通知 / 危機兆候領域 (= 専門家確認後に使うか判断)

### Step 1: 全成果物の一覧を作成 (allowlist 内のみ / 件数は問わない)
Claude が allowlist Glob で取得した `.md` ファイルから、以下の情報を含む全成果物一覧を作成して提示する:
- ファイル名 + Course / Part

- 作成時期 (Phase ID で代替)
- read_ok / skipped / reason

**件数は問わない** (Course 1-5 のうちファイルがある Phase が対象 / ファイルが無い Phase ID は明示して先へ進む)。

### Step 2: 4 区分（1 ターン 1 カテゴリ、redaction 状態を含む）
Claude が 1 ターンに 1 カテゴリずつ仕分け結果を提示し、受講者に「修正したい点はあるか」を 1 問だけ聞く:
- **渡せる** (件数は問わない / 該当なしも本人の今の実感として扱う): redact 済み or 含まない (= AI に直接渡せる)
- **加工必須** (件数は問わない / 該当なしも本人の今の実感として扱う): redact / 抽象化すれば渡せる (60202 で加工)
- **渡さない**: 自分だけが読む / redact 不能 (件数は問わない / 該当なしも本人の今の実感として扱う)
- **専門家確認**: 法務 / 医療 / 税務 / 労務 / 本番 Supabase / RLS / service_role / 課金 / 顧客通知 / 危機兆候 (該当があれば)

各ファイルに redaction 状態 (`redacted_ok` / `needs_redact` / `raw_only` / `expert_review`) を必ず記録。

### Step 3: 「渡せる + 加工必須」を深掘り + 不足文脈
Claude が「渡せる」+「加工必須」合計について (件数は問わない)、以下を表形式で提示する:
- どんな業務で使えるか
- そのまま渡せるか / 加工 (redact / 要約 / 抽象化) が必要か
- 不足している情報
- redaction 状態 (`redacted_ok` / `needs_redact` / `raw_only` / `expert_review`)

その後、**不足している文脈** (件数は問わない) + **Phase 60202 で再構成するフォルダ構成案** + **補完したい文脈候補** (件数は問わない / 複数可 / 該当なしも本人の今の実感として扱う)を提示し、受講者に修正案を 1 問だけ聞く。

### Step 4: 成果物を vault に書き戻す（競合検知 → Edit）
1. **競合更新再検知**: `~/sift/course6/part602/60201_context_inventory.md` をもう一度 Read し、0-D で保持した Step 3 / チェックリスト全文と比較
2. 差分があれば停止して受講者に確認 (1 問のみ)
3. 差分が無い or 受講者が「上書き OK」と回答した場合のみ、Step 3「成果物」セクションを Edit で書き込む
   - ファイルの Step 1 / Step 2 (このプロンプト) は触らない
   - Step 3 の全成果物一覧 / 4 分類結果 / 渡せる + 加工必須の深掘り / 不足文脈 / skipped list / 次の Phase へのメモ を 0-B redact ルールに従って埋める
   - チェックリストの該当項目に ✓ を入れる
   - 上書き前に必ず Read で現状を確認し、Step 3 が書き込み済みなら私に確認

## ルール
- **本人の希望を優先**し、途中で保留・休止・別の問いへの変更を選べるようにする。答えたくない理由は求めない
- **質問は 1 ターンに 1 つだけ**。複数選択肢の提示や複数項目の同時質問は禁止 (Step 0-F の 4 問まとめ提示は唯一の例外)
- 根拠がある部分と、推測の部分を分けて出力する
- まだ確定していない暫定判断には【仮説】マークをつける
- 「渡さない」「専門家確認」に分類したものも、消さない・移さない
- vault safety boundary / redaction 判定 / 競合更新検知 / Read 失敗例外のいずれかに違反する状況になったら、即停止して受講者に判断を仰ぐ
