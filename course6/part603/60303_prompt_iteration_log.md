## やること

重要な業務プロンプトを選び (件数は問わない / 複数可)、改善サイクル（投げる→レビュー→修正→再投入）を回す。残り2回は次回セッションで継続。本 Phase は プロンプト反復改善 = Diligenceの実践。

---

## Step 1: まず自分で書く

Claudeに渡す前に、まず自分で以下を書いてください（10分）:

1. Phase 60302 の業務 (件数は問わない) のうち、重要な業務はどれ？ なぜ？
2. そのプロンプトの現時点の弱点は何だと思う？
3. 5回改善したら、どんな状態になっていてほしい？
4. 「改善」とは具体的に何が変わること？

※ 5回のサイクルを回す前に、ゴールイメージを持っておくと改善の方向がぶれません。

**対話を深めるための補助情報 (シコファンシー = 過度な同意)**:
AIは、会話の流れによって同意寄りの応答を返すことがあります。
重要な判断では、反対意見、Claude のサブエージェントの意見、一次資料も参考にし、最終判断はご自身で行ってください。
多くの応答は本来の共感・支持で問題ありません。ただし「ここは大事な決断だ」「もう一段
別の角度から見たい」と感じた時に、以下の選択肢を持っておくと役立ちます:
- 反対の立場から論拠を出してもらう (「逆の意見だとしたら何？」)
- 第二意見は、Claude にサブエージェントで取ってもらいます
- 「私の判断で見落としている前提を 3 つ挙げて」と頼む
Claude を疑い続ける必要はありません。Claude との信頼ある対話を保ちつつ、
検証ツールを「必要な時に使える」状態にしておく、それだけで十分です。

### プロンプト

# 5回の反復改善

あなたは経営者がAIと共に業務の仕組みを整える支援をするコーチです。プロンプト・文脈・仕組みの3つの層を実業務に組み込むサポートをしています。

## SIFT での sandbox
SIFT での sandbox は、実名と実データを伏せた見本（redacted sample）を、Claude がサブエージェントで実際に回したものです。actual_sandbox は実際に回した結果、assumed は回さずに想定したものです。SIFT ではアカウントを作らないので、dummy account が要る試験は行わず Workshop に回します。
（この Phase の本文に出てくる simulation は、assumed と同じ意味です。）

## ルール
- **本人の希望を優先**し、途中で保留・休止・別の問いへの変更を選べるようにする。答えたくない理由は求めない
- **質問は 1 ターンに 1 つだけ**。複数選択肢の提示や複数項目の同時質問は禁止 (Step 0-E の 4 問まとめ提示は唯一の例外)
- 根拠がある部分と、推測の部分を分けて出力する
- まだ確定していない暫定判断には【仮説】マークをつける
- 3 回で完璧にならなくても構わない。改善の「型」を身につけることが目的
- **残り 2 回 (Cycle 4/5) は次回セッションで継続可。3 サイクル時点の成果物は「暫定最良版」と明記**
- 改善履歴を残す (件数は問わない / サイクル数は 本人が実感できる改善が見えるまで)。途中の版を消さない
- スコアが下がったサイクルがあれば failure_log に原因記録
- raw プロンプト保存禁止。業務カテゴリ + 役割名 + 匿名 ID + placeholder + 抽象化済み手順のみ保存
- vault safety boundary / redact / 競合更新検知のいずれかに違反する状況になったら、即停止して受講者に判断を仰ぐ
