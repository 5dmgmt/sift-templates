## 進め方（私に確認を取らずに開始してください）

### Step 0: 作業ファイル + 参照ファイルを読み、必要情報を揃える
1. **作業ファイル** `~/sift/course6/part603/60303_prompt_iteration_log.md` を Read で開き、Step 1 セクションの事前メモを取得
2. **参照ファイル** `~/sift/course6/part603/60302_structured_prompts.md` を Read で開く。Step 3 が空欄 or テンプレのままの場合、ここで停止して受講者に「Phase 60302 を先に完遂してください」と伝える
3. 事前メモが空欄なら、以下 4 問をまとめて 1 度に提示し、私の答えを待つ（A/B/C 選択肢は出さない）:
   - Phase 60302 の 3 件のうち、最も重要な業務はどれ / なぜか
   - そのプロンプトの現時点の弱点は何だと思うか
   - 5 回改善したら、どんな状態になっていてほしいか
   - 「改善」とは具体的に何が変わることか
4. 必要情報が揃ったら確認や進め方ヒアリングをはさまず即 Step 1 へ

### Step 1: 改善対象を 1 件選定 + 初期プロンプト確認
Claude が 60302 の 3 件から最もインパクトが大きい 1 件を選んで提示する (選定理由付き)。受講者に「この 1 件で進めるか / 修正したい点はあるか」を 1 問だけ聞く。

### Step 2: サイクル 1 (1 ターン)
Claude が初期プロンプトを実演:
- **実行**: プロンプト + 想定出力 (要約 5-10 行)
- **レビュー**: 成功条件と照らした評価 (0-10 点)
- **分析**: 足りない点 / 余計な点 (各 1〜3 件)
- **修正**: プロンプト改善 (変更点を明記)

提示後、受講者に「修正したい点はあるか」を 1 問だけ聞く。

### Step 3: サイクル 2 (1 ターン)
Claude がサイクル 1 の修正版を実演:
- **再投入**: 修正版プロンプト + 想定出力
- **レビュー**: スコア (0-10)
- **分析 + 次の修正**

受講者に「修正したい点はあるか」を 1 問だけ聞く。

### Step 4: サイクル 3 + 改善傾向分析 + 最終版テンプレート（1 ターン）
Claude がサイクル 3 を実演し、まとめて以下を提示する:
- **サイクル 3**: プロンプト + 想定出力 + スコア + 分析
- **スコア推移表**: サイクル 1/2/3 (4/5 は次回継続)
- **最も効果が大きかった修正**: 1 件 + 根拠
- **これ以上改善が難しい部分**: 1〜2 件
- **failure_log**: スコアが下がったサイクルがあれば原因記録 (該当があれば)
- **プロンプト改善の 3 大原則 (自分なりの発見)**: 3 件
- **最終版テンプレート**: サイクル 3 終了時点の最良版 (5 要素構造)

最後に「Part 604 で仕組みに組み込む際の注意点」を Claude が提示し、受講者に修正案を 1 問だけ聞く。

### Step 5: 成果物を vault に書き戻す
`~/sift/course6/part603/60303_prompt_iteration_log.md` の Step 3「成果物」セクションを Edit で書き込む。
- ファイルの Step 1 / Step 2 (このプロンプト) は触らない
- Step 3 の改善対象 / サイクル 1-3 / スコア推移 / 改善分析 / 最終版テンプレート / 次の Phase へのメモ を埋める (4/5 は空欄のまま、次回継続)
- チェックリストの該当項目に ✓ を入れる
- 上書き前に必ず Read で現状を確認し、Step 3 が書き込み済みなら私に確認

## ルール
- **進め方の確認・好みヒアリングは禁止**。上記の手順で決め打ちで進める
- **質問は 1 ターンに 1 つだけ**。複数選択肢の提示や複数項目の同時質問は禁止
- 根拠がある部分と、推測の部分を分けて出力する
- まだ確定していない暫定判断には【仮説】マークをつける
- 3 回で完璧にならなくても構わない。改善の「型」を身につけることが目的
- 残り 2 回は次回セッションで継続可
- 3 回分以上の改善履歴を残す。途中の版を消さない
- スコアが下がったサイクルがあれば failure_log に原因記録
