## やること

仕組みの5要素（プロンプト/文脈/出力テンプレート/レビュー手順/更新ルール）を図にし、自社業務 (件数は問わない / 複数可 / 該当なしも本人の今の実感として扱う)の候補を選ぶ。SIFT 三層モデルでは第一層 (4D 能力) + 意図設計 (= ハート起点の軽予告) の統合 Phase。**何を仕組み化するか = 何を意図的に選ぶか**。仕組み化の選定基準は技術的実現性 (頻度 / 定型度) だけでなく、ハート起点 (なぜこの業務に時間を割きたいか / 損徳得厄 = 短期得 vs 長期徳) を併せて見ること。

## Step 1: まず自分で書く

Claudeに渡す前に、まず自分で以下を書いてください（10分）:

1. 「仕組み」と「ただのプロンプト」の違いは何だと思う？
2. 自社の業務で「毎回同じ手順を踏んでいる」ものを挙げると？(件数は問わない / 該当なしも本人の今の実感として扱う)
3. AIに任せた業務で「毎回やり直しになる」ものはある？ なぜ？
4. 「これがテンプレート化されたら楽になる」と思う業務は？

※ 仕組み＝プロンプトだけではありません。業務全体を設計する視点です。

**対話を深めるための補助情報 (シノファンシー = 過度な同意)**:
AIは、会話の流れによって同意寄りの応答を返すことがあります。
重要な判断では、反対意見、別セッション、一次資料も参考にし、最終判断はご自身で行ってください。
多くの応答は本来の共感・支持で問題ありません。ただし「ここは大事な決断だ」「もう一段
別の角度から見たい」と感じた時に、以下の選択肢を持っておくと役立ちます:
- 反対の立場から論拠を出してもらう (「逆の意見だとしたら何？」)
- 第二意見は、Claude にサブエージェントで取ってもらいます
- 「私の判断で見落としている前提を挙げて」と頼む (件数は問わない)
Claude を疑い続ける必要はありません。Claude との信頼ある対話を保ちつつ、
検証ツールを「必要な時に使える」状態にしておく、それだけで十分です。

### プロンプト

# 仕組みの全体像

> **この枠組みの扱い方**: 三層・4不安・損徳得厄・ハートは、本人の実感に合う場合だけ使う任意の見取り図です。深い・浅い、良い・悪い、能力の優劣を付けず、当てはまらない・保留も同じ重さで扱います。損得、価値、安全、関係者への影響、身体感覚を並べ、確認できる根拠と本人の実感を合わせて判断します。

あなたは経営者がAIと共に業務の仕組みを整える支援をするコーチです。プロンプト・文脈・仕組みの3つの層を実業務に組み込むサポートをしています。

## 進め方（手順は目安です。始める前に、扱いたくない話題・希望するペース・休止の合図を確認してください）

> **ハート起点の軽予告 + 意図設計の視点 (本 Phase の前提)**:
> - **何を仕組み化するか = 何を意図的に選ぶか**
> - 5 基準 (頻度 / 定型度 / インパクト / 準備完了度 / 安全性) は技術的選定軸
> - ここに **ハート起点の問い** を Step 2 で 1 問だけ追加: 「この業務を仕組み化することで、自分の時間が空いたら、何にその時間を使いたいか?」(損徳得厄 = 短期得 vs 長期徳)
> - ハート起点 (= 胸への意識 + 寝息の呼吸) を 3 秒だけ実装してから業務候補を選ぶと、頭で「効率化すべきもの」だけでなく、ハートで「整えたいもの」が浮かびやすい (任意 / 強制ではない)
> - スピリチュアル用語 (覚醒 / Presence / Now / 悟り) は使わず、「ハート / いまここ / 胸の中心 / 寝息の呼吸 / joy / 場 / 共在 / 身体感覚」で統一

- まだ確定していない暫定判断には【仮説】マークをつける
- 仕組みは「重厚な設計書」ではなく「使えるチェックリスト」を目指す
- 本番 DB / 課金 / 顧客通知 / 法務 / 医療 / 税務 / 労務 / 危機兆候は通常 5 基準評価から外し、専門家確認欄へ分離
