## やること

文脈の量と種類を変えた3条件で実験し、どんな文脈がどれだけ出力を変えるかを定量的に把握する。Course 6 = SIFT 三層モデル第三層 entry (ハート起点) 本格実装コースのうち、本 Phase は文脈の使い分け技術 (第一層 4D 能力スキルと連動 / Course 6 全体は第三層 ハート起点 の入口体感)。

### Step 1: 業務課題を 1 件選ぶ + 安全領域分離
Claude が業務候補を 1〜3 件提示し、受講者に「どれを実験対象にするか」を 1 問だけ聞く (60101 と同じでも別でも可)。
**通常実験から外す停止条件 (= 別欄送り)**:
- 本番 Supabase 操作 / RLS 緩和 / service_role 使用 / migration 実行 / DB 構造変更
- 課金 / 決済 / 価格変更 / 解約処理

- 違法行為 / DV / 自殺念慮等の危機兆候保護領域
- 受講者がこれらに該当する課題を選んだ場合、通常 3 条件比較から分離し、「人間最終責任者 + 専門家確認欄」へ送る (Claude は draft / sandbox / read-only での比較のみ実施)

### Step 2: 3 条件をサブエージェントで実際に回して並べる（1 ターン 1 条件、文脈は redacted で渡す）
Claude が同じプロンプトに以下 3 種類の文脈を渡した条件ごとに、サブエージェント (Agent ツールで起動する別の作業役) に、その条件の文脈だけを渡して実際に回し、1 ターンに 1 条件ずつ実際の出力 (要約) を提示し、受講者に「修正したい点はあるか」を 1 問だけ聞く。3 条件の出力は、最後に並べて見せる。サブエージェントが使えないときは「回せなかった」と記録し、想定した出力は「想定 (assumed)」と明記する:
- **条件 A**: 自分の基本情報だけ (事業概要 / 役職 / 業界) — PII placeholder
- **条件 B**: 条件 A + 業務固有の文脈 (過去の成果物 / 業務手順 / 対象者の情報) — 0-B の redact ルールに従う
- **条件 C**: 条件 B + 自己理解の文脈 (Course 1-5 から価値観 / 得意・苦手 / 意思決定スタイル) — Course 1-5 vault から条件 C 用に最大 3 ファイルまで Read してよい

### Step 3: 比較表 + A→B / B→C 変化点 + コンテクスト効果マップ
Claude が以下を提示する:
- **3 条件比較表**: 4 観点 (的確さ / 具体性 / トーンの適切さ / そのまま使えるか) × 条件 A/B/C (12 セル全埋め)
- **A → B で変わった点** (業務文脈の効果): 件数は問わない (専用欄)
- **B → C で変わった点** (自己理解文脈の効果): 件数は問わない (専用欄)
- **コンテクスト効果マップ**: 文脈の種類 × 効果が出た観点 × 効果の大きさ (件数は問わない / 同形式で追加)
- **効果が大きかった文脈候補の種類**: (件数は問わない / 複数可) + 理由
- **文脈を増やしても変わらなかった部分**: (件数は問わない / 該当なしも本人の今の実感として扱う)
- **文脈が逆効果になった点 (failure_log)**: (件数は問わない / 該当なしも本人の今の実感として扱う)

最後に受講者に修正案を 1 問だけ聞く。

### Step 4: 成果物を vault に書き戻す（競合検知 → Edit）
1. **競合更新再検知**: `~/sift/course6/part601/60102_context_effect_test.md` をもう一度 Read し、0-D で保持した Step 3 / チェックリスト全文と比較
2. 差分があれば停止して受講者に確認 (1 問のみ)
3. 差分が無い or 受講者が「上書き OK」と回答した場合のみ、Step 3「成果物」セクションを Edit で書き込む
   - ファイルの Step 1 / Step 2 (このプロンプト) は触らない
   - Step 3 の 3 条件設計 / 比較表 / A→B / B→C / 効果マップ / 気づき / 次の Phase へのメモ を 0-B redact ルールに従って埋める
   - チェックリストの該当項目に ✓ を入れる
   - 上書き前に必ず Read で現状を確認し、Step 3 が書き込み済みなら私に確認

## ルール
- **本人の希望を優先**し、途中で保留・休止・別の問いへの変更を選べるようにする。答えたくない理由は求めない
- **質問は 1 ターンに 1 つだけ**。複数選択肢の提示や複数項目の同時質問は禁止 (Step 0-E の 4 問まとめ提示は唯一の例外)
- 根拠がある部分と、推測の部分を分けて出力する
- まだ確定していない暫定判断には【仮説】マークをつける
- 「文脈は多いほど良い」と決めつけず、逆効果になるケースも探す
- vault safety boundary / 文脈安全境界 / 安全領域分離 / 競合更新検知のいずれかに違反する状況になったら、即停止して受講者に判断を仰ぐ
