## 進め方（私に確認を取らずに開始してください）

### Step 0: 作業ファイル + 参照ファイル 2 件を読み、必要情報を揃える
1. **作業ファイル** `~/sift/course3/part303/30303_business_purpose_statement.md` を Read で開き、Step 1 セクションの事前メモを取得
2. **参照ファイル 2 件** をすべて Read で開く。いずれか 1 件でも Step 3 が空欄 or テンプレのままの場合、ここで停止して受講者に「Phase 30301 / 30302 のうち未完遂のものを先に完遂してください」と該当 Phase ID を明示して伝える
3. 事前メモが空欄なら、以下 3 問をまとめて 1 度に提示し、私の答えを待つ（A/B/C 選択肢は出さない）:
   - 30301 (創業の原点) と 30302 (価値の現実) を踏まえて、事業の目的を 1 文で書くとしたら？
   - 自分の事業で「絶対にやりたくないこと」は？
   - 目的ステートメントに入れたくない言葉 (曖昧すぎる、嘘っぽい等) は？
4. 必要情報が揃ったら確認や進め方ヒアリングをはさまず即 Step 1 へ

### Step 1: 3 パターンのステートメントを起草する（決め打ち）
30301-30302 の事実をベースに、Claude が以下 3 パターンを提示する:
1. **1 文版**: 20 字以内で核心だけ
2. **3 文版**: 誰に / 何を / なぜ、を含む
3. **禁止事項付き版**: 目的 + 「これは目的ではない」+「この手段は使わない」

提示後、受講者に「修正したいパターンはあるか」を 1 問だけ聞く。

### Step 2: 曖昧語を削る
Claude が 3 パターンを以下の観点でチェックし、曖昧語があれば「元の表現 → 問題点 → 修正後」の表で提示する:
- 「〜に貢献する」「〜を実現する」「〜の力になる」等の曖昧な動詞
- 「イノベーション」「ソリューション」「エンパワーメント」等のバズワード
- 誰にでも当てはまる表現

提示後、受講者に「修正案を変えたい点はあるか」を 1 問だけ聞く。

### Step 3: 最終版を 1 本選ぶ + 使わない言葉リスト
Claude が 3 パターンから最終版を 1 本推奨提示する。各パターンの「採用理由 / 却下理由」を併記。
受講者に「最終版を入れ替えるか」を 1 問だけ聞く。
最後に「使わない言葉リスト」を 5 件以上 Claude が事前メモ + 曖昧語チェックから抽出して提示する。

「Claude が美しいステートメントを提案しても、本人の言葉でなければ却下する」を Claude が必ず受講者に促す。

### Step 4: 成果物を vault に書き戻す
`~/sift/course3/part303/30303_business_purpose_statement.md` の Step 3「成果物」セクションを Edit で書き込む。
- ファイルの Step 1 / Step 2 (このプロンプト) は触らない
- Step 3 の 3 パターン / 曖昧語チェック / 最終ステートメント / 採用理由 / 却下案理由 / 使わない言葉リスト / Part 303 統合メモ / 次の Part へのメモ を埋める
- チェックリストの該当項目に ✓ を入れる
- 上書き前に必ず Read で現状を確認し、Step 3 が書き込み済みなら私に確認

## ルール
- **進め方の確認・好みヒアリングは禁止**。上記の手順で決め打ちで進める
- **質問は 1 ターンに 1 つだけ**。複数選択肢の提示や複数項目の同時質問は禁止
- 根拠がある部分と、推測の部分を分けて出力する
- まだ確定していない暫定判断には【仮説】マークをつける
- 私が別途確認すべき点があれば最後にまとめる
- Claude が「きれいなステートメント」を提案しても、本人の言葉でなければ却下する
